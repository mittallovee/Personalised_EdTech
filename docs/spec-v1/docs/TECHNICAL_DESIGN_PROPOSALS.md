# Technical Design Proposals

Prepared 18 October 2026. **Every P-number below is an assistant engineering proposal for review, not an additional user-confirmed requirement.** Confirmed policy remains in D-01–D-23. These recommendations close routine design choices without extending the product questionnaire.

## Proposed defaults

| ID | Area | Recommendation |
| --- | --- | --- |
| P-01 | Service shape | Next.js/React/TypeScript web, FastAPI service, SQLAlchemy/Alembic, PostgreSQL/JSONB/RLS, Redis broker and Celery Linux workers; one modular repository, no microservice split |
| P-02 | Local runtime | Linux containers via Docker Desktop/WSL2 if local prerequisites/licensing fit; private persistent filesystem behind an object-store interface initially. Linux services in WSL2 are an alternative if Docker is unsuitable. Do not run Celery natively on Windows |
| P-03 | Dependency selection | Pin supported compatible releases in lockfiles at implementation; do not infer installed versions or choose an unverified latest version in this document. LiteLLM is optional behind project adapters, not a mandatory dependency |
| P-04 | Public codes | Eight uppercase characters A–Z/0–9, cryptographic random generation, global unique constraint and bounded collision retries. Case-insensitive input normalized uppercase. Codes never recycled; archive preserves reservations |
| P-05 | Draft revisions | Each saved change appends an immutable revision with parent/hash/actor. One active editable version per master; published snapshots immutable. Corrections to published content create a new version |
| P-06 | Workflow binding | QC, approval and publication refer to an exact revision/hash. Editing reviewed/approved content returns the working version to DRAFT and invalidates current QC/approval eligibility; old evidence remains. Enforce optimistic concurrency |
| P-07 | Faculty editing | Creator may edit own unpublished work; admin may edit coaching work; other faculty need cross-author-edit grant. Formal QC permission alone permits findings/return/pass, not arbitrary content rewrites. Applied AI corrections use these same write checks |
| P-08 | Initial role implementation | Fixed platform admin/Owner/admin/faculty roles and independent QC/approve/publish/cross-author-edit grants. Custom role-builder UI deferred. Owner/admin administer ordinary faculty grants; only Owner/platform changes admin/Owner authority |
| P-09 | Canonical identity | One user with verified method links; local email/password auth with Argon2id, Google OAuth/OIDC adapter and SMS OTP transport adapter. Explicit method-control verification; no email/phone-match auto merge. Choose maintained libraries after dependency review |
| P-10 | Sessions | Opaque random server sessions, hashed session tokens, HttpOnly cookies, CSRF protection, secure cookies on HTTPS. Proposed 12-hour idle/7-day absolute session lifetimes configurable; no device-count cap introduced. Membership/role removal checked on requests and job writes, backend revocation across sessions |
| P-11 | Activation/recovery | Admin-generated one-time activation links with 24-hour expiry and verified method enrollment. Display/copy link in app; no notification email delivery. Reauthentication for sensitive changes; recovery cannot silently merge accounts or restore revoked membership |
| P-12 | API conventions | /api/v1, UUID resources, RFC3339 UTC timestamps, explicit trusted target context, safe structured errors, ETag/If-Match for mutations, opaque cursor lists default 50/max 100 items. Search/counts never scan-return the whole bank |
| P-13 | Idempotency | Actor+organization+operation+key binds request hash/result. Same request replays same result; changed payload conflicts. Keep operation mappings for job/copy lifetime, not merely a short HTTP cache |
| P-14 | Rich content | Versioned typed blocks for paragraphs, equations, images, tables. Equations preserve supplied LaTeX/MathML or visual-derived source and renderer provenance; unsupported conversion visible, never silently lossily replace source |
| P-15 | Answers | Stable option/item IDs, integers as integers, numerical values as decimal strings with exactly two places. No binary floats or unit field. Explicit exact/range union; imported overprecision/multiple ranges stays unresolved evidence |
| P-16 | Taxonomy references | Normalized hierarchy and stable concepts with localized labels; version snapshots pin labels/assignments. Same-subject concepts may cross topic/chapter/class branches; no requirement to erase valid secondary concepts outside the main topic |
| P-17 | Graph | Directed prerequisite → dependent acyclic graph. Check cycles before immediate activation; conflicting proposal remains visible/unresolved rather than silently dropping links. Cross-class allowed, cross-subject denied. Revoked concepts/edges excluded from new automatic selection |
| P-18 | Upload transport | Decimal MB: 50,000,000 document bytes/10,000,000 image bytes. Proposed configurable submission bound 20 files/500,000,000 bytes; split larger imports into jobs without narrowing lakh-scale bank scope. PDF/DOCX/DOC plus raster JPEG/PNG/WebP/TIFF/BMP; HEIF/HEIC through a verified conversion path, visible unsupported-decoder errors |
| P-19 | Parser limits | Isolated conversion/recognition, bounded CPU/memory/time and decompression/pixel/page resources. Initial numeric parser ceilings derived from representative fixtures before engine release; hit limits visibly and retain sources. No arbitrary executable/ZIP upload support inferred |
| P-20 | Worker behavior | Durable SQL jobs/attempts/checkpoints; Redis not the sole record. Transactional event/outbox dispatch for queue/app events (not email). Initial worker concurrency 1 per heavy queue; configurable after measurement |
| P-21 | Retry/cancel | Retry transient errors at most 3 dispatch attempts per stage, e.g. 2s/10s bounded backoff plus jitter, honoring provider Retry-After. Do not retry auth/validation failures blindly. Cooperative cancel stops future work; retain complete drafts and report in-flight billing honestly |
| P-22 | Pattern lifecycle | Candidate → usable after successful structural/coverage validation on discovery material; automatic selection of usable versions. Drift marks affected work unresolved/fallback, never skips source content. Candidate/disabled/deprecated versions remain historical |
| P-23 | Duplicate disposition | Hash/structure candidates first, bounded semantic retrieval as needed. Human-confirmed exact intake attaches source without new code; variants/translations distinct. Existing duplicate masters receive non-destructive links; no automatic destructive merge |
| P-24 | Generation bounds | Propose initial maximum 10 variant outputs per request with mixed per-group targets and one-request instructions; configurable. No source-review gate for variants. Translation requires source review; outputs follow own QC |
| P-25 | Credential management | Encrypted per-coaching secrets, separate local master key outside repo/DB, write-only UI, masked status/version/last validation. Rotation/revocation audited without plaintext; workers resolve current authorized credential version. Full platform administration need not expose raw secrets |
| P-26 | Provider fallback | Explicit ordered enabled compatible catalogue list, each attempted at most once within the 3-attempt stage bound. Fail visibly before switching; never use another coaching's key or ignore refusal/security restrictions to force an answer. Record route/upstream model when available |
| P-27 | Budget accounting | Calendar month in configurable coaching timezone, default Asia/Kolkata. Atomic reservations before dispatch including retry/fallback estimates; reconcile actual/estimated/unavailable. Attribute late evidence to the original dispatch period. Unknown bounded cost pauses dispatch until admin resolves pricing, rather than treat unknown as zero |
| P-28 | Budget setup | AI calls require configured keys and a usable per-faculty limit/accounting basis. No numerical spending amount or unlimited default inferred. At 80% emit one deduplicated warning per period; at 100% stop new dispatch/reservations. Late actual usage may exceed a reserved estimate; report overrun honestly |
| P-29 | Taxonomy notifications | Transactionally create in-app alerts for active coaching admins including Owner; one event/entity revision with per-recipient read state. New admin receives current review queue, no fabricated past personal delivery. Processing continues if UI delivery is delayed; no emails |
| P-30 | Original deletion | Tombstone original availability; unlink only original storage ownership after checking independent question/pattern/copy assets. Async deletion receipts and audit. Active ingestion/copy pins return SOURCE_IN_USE (409); admin may cancel/await completion then retry, rather than deleting in-flight input. Historical source metadata remains; no hard question deletion |
| P-31 | Dataset copy | Consistent source cutoff manifest, destination-owned IDs/assets/new question codes, immutable mapping keys. Copy current educational dataset plus history/dependencies; exclude live jobs, login/grants/secrets and spend-ledger replay. Preserve operational provenance as inert evidence |
| P-32 | Nonempty target | Import into a distinct provenance namespace. Flag potential semantic duplicates; retain independent new identities for this explicit educational seed copy rather than ordinary intake duplicate collapse. Block unresolved taxonomy/dependency conflicts and never overwrite existing destination work |
| P-33 | Copy completion | Stage and validate complete dependency components; activate a complete validated component transactionally, preserving source publication states. Report PARTIAL when components fail. Retry missing items through existing mapping; do not resync or overwrite edited destination objects |
| P-34 | Local backups | Daily logical database export and asset manifest/copy; proposed 7 daily + 4 weekly retained sets, plus pre-migration checkpoint. Keep encrypted off-machine copy before relying on real data; verify restore in an isolated environment. These are defaults, not achieved RPO/RTO |
| P-35 | Accessibility/UI | Responsive faculty/admin layout, keyboard navigation, clear saved/error/pending states, math source/preview and Unicode fonts. No universal full UI translation or standards certification inferred from question-language support |

## How proposals are used

The next review assesses this concrete baseline, rather than asking the user every implementation detail. Before code, confirm the first executable slice and resolve material design objections. During implementation, record evidence-driven refinements and preserve confirmed product policy.

Production hosting, SMS vendor, exact model catalogue, operational recovery guarantees, source-engine benchmarks and later product modules remain milestone gates. They do not reopen the current interview. [Official references](TECHNICAL_REFERENCES.md) support integration boundaries; no live integrations or compatibility tests have run.
